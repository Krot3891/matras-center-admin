# matras-center-admin — адмін-панель (Етап 0)

Окремий проєкт. Не торкається і не залежить від основного сайту
matras-center.ua (того HTML/CSS/JS, який вже існує і ще дороблятиметься).

## Статус на Етапі 0

Це каркас: сторінки й маршрутизація готові, але без реальної бізнес-логіки.

- `/login` — працює: надсилає email і пароль на `POST /auth/login` API,
  зберігає отриманий JWT у `localStorage` (ключ `adminToken`), при помилці
  показує повідомлення, після успіху веде на `/products`.
- `/products`, `/products/new` і `/products/:id/edit` закриті: без чинного (наявного й не простроченого)
  токена перенаправляють на `/login`. Це захист інтерфейсу — доступ до даних
  все одно перевіряє сервер. Якщо сервер відповідає `401`, токен видаляється
  і відкривається `/login`.
- `/products` — список товарів із публічного `GET /products`.
- `/products/new` — форма додавання товару працює: категорії беруться з `GET /categories`
  (випадаючий список), збереження — авторизований `POST /products` (JWT з `localStorage`),
  після успіху — повернення на `/products`. Помилки сервера (некоректні поля, зайнятий SKU,
  недоступна категорія, мережа) показуються над кнопкою. `slug` створює сервер.
  Категорія обов'язкова: якщо категорій ще немає, спершу створіть її (`POST /categories`,
  див. README `matras-center-api`).
- `/products/:id/edit` — редагування товару (кнопка «Редагувати» у списку). Та сама форма, заповнена поточними
  даними; збереження — авторизований `PATCH /products/:id`, надсилаються лише змінені поля, після успіху —
  повернення на `/products`. Помилки API показуються над кнопкою, введені дані зберігаються. Окремого
  `GET /products/:id` в API немає, тому товар береться з публічного `GET /products` (лише опубліковані).
  `slug` і фото не змінюються.
- **Фото товару** у формах створення й редагування: вибір файлів (JPEG/PNG/WebP, до 5 МБ, до 10 на товар),
  прев'ю до збереження, кнопка ✕ для прибирання вибраного, помилки по кожному файлу. Фото завантажуються
  при натисканні «Зберегти»:
  - створення: кожен файл → `POST /uploads/images` (поле `file`, JWT) → отримані URL надсилаються в `POST /products`
    як `images`; якщо створення товару не вдалося, повторно файли не вантажаться;
  - редагування: спершу `PATCH` змінених полів, потім кожен новий файл → `POST /products/:id/images`
    (завантаження + прив'язка до товару). Якщо якесь фото не завантажилось, дані товару вже збережено, а проблемні
    фото лишаються у формі для повторної спроби.
  Потрібно, щоб на API були налаштовані змінні `R2_*` (інакше сервер відповідає, що сховище не налаштоване).
  Видалення і зміна порядку збережених фото, а також alt-текст поки не підтримуються в інтерфейсі.

API за замовчуванням — `https://matras-center-api.onrender.com`; змінити можна
через `VITE_API_URL`. Домен адмінки має бути в `ALLOWED_ORIGINS` на боці API,
інакше браузер заблокує запити (CORS).

## Як запустити локально

```bash
npm install
cp .env.example .env
# у .env вкажіть адресу локального API, наприклад http://localhost:4000
npm run dev
```

За замовчуванням Vite піднімає адмінку на `http://localhost:5173`.
Перевірка: `npm test` (правила вибору фото), `npm run build`.
Для роботи сторінки товарів потрібен запущений `matras-center-api`
(див. README цього проєкту) — інакше запит до `/products` впаде з
помилкою з'єднання, яку сторінка коректно покаже.

## Структура

```
src/
  main.jsx          — точка входу, BrowserRouter
  App.jsx           — маршрути: /login, /products, /products/new, /products/:id/edit
  lib/api.js        — обгортка над fetch (базовий URL + токен з localStorage; підтримує FormData)
  lib/photoRules.js — правила вибору фото (тип, розмір, ліміт) і тексти помилок завантаження
  pages/
    Login.jsx        — каркас логіну (без реальної перевірки)
    ProductsList.jsx — список товарів (реально читає GET /products)
    ProductForm.jsx  — форма товару: додавання і редагування
```

## Деплой

Не виконувався і не планується в рамках Етапу 0. Коли дійде до
Етапу 1+, планується окремий субдомен `admin.matras-center.ua` —
але створення цього субдомену і будь-яка зміна DNS відбудеться
тільки після вашого окремого підтвердження.
